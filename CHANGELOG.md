## [Unreleased]

### Highlights

- First-class discrete modes and density (issue #9): documents declare their modes, color tokens carry generalized mode→value maps (light/dark fields remain as sugar), and foundations gain density variants with spacing multipliers and overrides

### Added

- DesignSystem.modes declaration and ColorToken.modes / ThemeToken.defaults mode→value maps with EffectiveModes/EffectiveDefaults sugar folding; Foundations.densities with scale and per-token spacingOverrides; ThemeToken.densitySensitive; themeMode accepts any declared mode
- mode-completeness spec lint rule: mode-aware tokens must cover every declared mode, undeclared mode keys are flagged, and documents using modes without declaring them get an advisory
- CSS generation emits [data-mode] override blocks and a --density scale property with per-density [data-density] blocks across tailwind4 and css-vars; scss gains per-mode and density variables; mkdocs-material picks dark-mode token values where defined
- Theme bindings resolve per-mode values across explicit, semantic, and inherit strategies; W3C export carries the full modes map and a density group; LLM context gains a Modes column and Densities section
