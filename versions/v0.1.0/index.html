    Design System Specification¶

    Version 0.1.0¶

    The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 RFC2119 RFC8174 when, and only when, they appear in all capitals, as shown here.

    Introduction¶

    The Design System Specification (DSS) defines a standard, machine-readable format for describing design systems. A DSS document describes:

    • Foundations: Design tokens including colors, typography, spacing, and other primitive values
    • Components: Reusable UI elements with their props, events, slots, and constraints
    • Patterns: Multi-component solutions for common UX scenarios
    • Accessibility: System-wide and component-level a11y requirements
    • LLM Context: Metadata optimized for AI-assisted code generation

    Goals¶

    1. AI-Native Development: Enable AI agents to generate design-system-compliant code
    2. Code Generation: Support generating CSS, TypeScript types, and documentation
    3. Validation: Enable automated checking of implementations against the spec
    4. Interoperability: Provide a common format for design system tooling

    Definitions¶

    DSS Document¶

    A document (or set of documents) that defines or describes a design system. A DSS document MUST be a valid JSON or YAML document.

    Path Templating¶

    Not applicable to this specification.

    Media Types¶

    The DSS document SHOULD be served with a media type of application/json or application/yaml.

    HTTP Status Codes¶

    Not applicable to this specification.

    Specification¶

    Versions¶

    The DSS Specification is versioned using a major.minor.patch versioning scheme. The major.minor portion of the version string (e.g., 0.1) SHALL designate the DSS feature set.

    Format¶

    A DSS document is itself a JSON object, which MAY be represented either in JSON or YAML format.

    All field names in the specification are case-sensitive.

    The schema exposes two types of fields: Fixed fields and Patterned fields.

    Fixed fields have a declared name. Patterned fields declare a regex pattern for the field name.

    Data Types¶

    Primitive data types in the DSS are based on the types supported by JSON:

    Type Format Description
    string A sequence of characters
    number A numeric value (integer or decimal)
    integer A whole number
    boolean true or false
    array An ordered list of values
    object A key-value map

    Rich Text Formatting¶

    Throughout the specification description fields are noted as supporting CommonMark markdown formatting.

    Relative References¶

    Not applicable to this specification. All URLs MUST be absolute.

    Schema¶

    Design System Object¶

    This is the root object of the DSS document.

    Fixed Fields¶

    Field Name Type Description
    meta Meta Object REQUIRED. Provides metadata about the design system.
    principles [Principle Object] Design philosophy and brand values.
    foundations Foundations Object REQUIRED. Design tokens and primitive values.
    components [Component Object] Reusable UI elements.
    patterns [Pattern Object] Multi-component UX solutions.
    templates [Template Object] Page-level layouts.
    content Content Object Voice, tone, and content guidelines.
    accessibility Accessibility Object System-wide accessibility requirements.
    governance Governance Object Versioning and contribution policies.

    Design System Object Example¶

    {
  "meta": {
    "name": "Acme Design System",
    "version": "1.0.0",
    "description": "The official design system for Acme products"
  },
  "foundations": {
    "colors": [
      { "id": "primary", "value": "#3b82f6", "usage": "Primary actions" }
    ]
  },
  "components": [
    {
      "id": "button",
      "name": "Button",
      "description": "Interactive button component"
    }
  ]
}

    Meta Object¶

    Provides metadata about the design system.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. The design system name.
    version string REQUIRED. The version following semantic versioning.
    description string A brief overview of the design system. CommonMark syntax MAY be used.
    maturityLevel integer System maturity level from 1 (experimental) to 5 (stable).
    repository string URL to the source repository. MUST be a valid URI.
    documentation string URL to the documentation site. MUST be a valid URI.
    maintainers [Maintainer Object] People or teams responsible for the system.
    license string The license identifier (e.g., "MIT", "Apache-2.0").

    Meta Object Example¶

    {
  "name": "Acme Design System",
  "version": "2.1.0",
  "description": "A modern design system for building Acme applications",
  "maturityLevel": 4,
  "repository": "https://github.com/acme/design-system",
  "license": "MIT"
}

    Maintainer Object¶

    Represents a person or team responsible for the design system.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. Name of the maintainer or team.
    email string Email contact. MUST be a valid email format.
    url string URL to profile or team page. MUST be a valid URI.

    Foundations Object¶

    Contains design tokens and primitive values.

    Fixed Fields¶

    Field Name Type Description
    colors [Color Token Object] Color palette and semantic color tokens.
    typography Typography Object Font families, sizes, weights, and type scale.
    spacing Spacing Scale Object Spacing scale for margins, padding, and gaps.
    elevation [Elevation Token Object] Shadow/depth tokens for layering.
    motion Motion System Object Animation and transition tokens.
    grid Grid System Object Layout grid system.
    breakpoints [Breakpoint Object] Responsive breakpoints.
    borderRadius [Border Radius Token Object] Corner radius tokens.
    borderWidth [Border Width Token Object] Border width tokens.
    opacity [Opacity Token Object] Opacity scale tokens.
    zIndex [Z-Index Token Object] Z-index layer tokens.

    Color Token Object¶

    Represents a single color in the design system.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier (e.g., "primary-500").
    value string REQUIRED. Color value in hex, rgb, rgba, or hsl format.
    semantic string Color's purpose (primary, secondary, danger, etc.).
    usage string When and how to use this color. CommonMark syntax MAY be used.
    contrast Contrast Object Accessibility contrast information.
    lightModeValue string Alternate value for light mode.
    darkModeValue string Alternate value for dark mode.

    Color Token Object Example¶

    {
  "id": "primary",
  "value": "#3b82f6",
  "darkModeValue": "#60a5fa",
  "semantic": "primary",
  "usage": "Primary actions and interactive elements"
}

    Typography Object¶

    Defines the type system.

    Fixed Fields¶

    Field Name Type Description
    fontFamilies [Font Family Object] REQUIRED. Available font stacks.
    fontSizes [Font Size Object] REQUIRED. Font size scale.
    fontWeights [Font Weight Object] REQUIRED. Available font weights.
    lineHeights [Line Height Object] REQUIRED. Line height scale.
    letterSpacings [Letter Spacing Object] Letter spacing scale.
    typeScale [Type Style Object] Complete type styles.

    Font Family Object¶

    Represents a font stack.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier (e.g., "sans", "serif", "mono").
    name string REQUIRED. Display name for the font family.
    stack string CSS font-family fallback stack.
    value string Deprecated. Use stack instead.
    weights [integer] Available font weights (e.g., [400, 500, 700]).
    source string URL to load the font (e.g., Google Fonts URL).
    usage string When to use this font family.

    Spacing Scale Object¶

    Defines the spacing system.

    Fixed Fields¶

    Field Name Type Description
    baseUnit string REQUIRED. Fundamental spacing unit (e.g., "4px").
    scale [Spacing Token Object] REQUIRED. Spacing tokens.

    Spacing Token Object¶

    Represents a single spacing value.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier (e.g., "xs", "sm", "md").
    value string REQUIRED. Spacing value with unit.
    pixelValue integer Equivalent pixel value for reference.

    Component Object¶

    Represents a reusable UI element.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier (e.g., "button", "modal").
    name string REQUIRED. Display name for the component.
    description string Overview of the component's purpose. CommonMark syntax MAY be used.
    category string Groups related components (e.g., "inputs", "navigation").
    variants [Variant Object] Different visual or behavioral versions.
    states [State Object] Interactive states (hover, focus, disabled).
    props [Prop Object] Configurable properties/attributes.
    events [Component Event Object] CustomEvents emitted by the component.
    slots [Slot Object] Content insertion points for composition.
    uses [string] Component IDs that this component depends on.
    tokensUsed [string] Foundation token IDs used by this component.
    constraints Constraints Object Usage limitations and requirements.
    accessibility Component A11y Object Accessibility requirements.
    llm LLM Context Object AI code generation optimization fields.
    documentationUrl string URL to detailed documentation. MUST be a valid URI.
    figmaUrl string URL to Figma component. MUST be a valid URI.

    Component Object Example¶

    {
  "id": "button",
  "name": "Button",
  "description": "Interactive button for triggering actions",
  "category": "inputs",
  "props": [
    {
      "name": "variant",
      "type": "string",
      "default": "primary",
      "enumValues": ["primary", "secondary", "destructive"]
    },
    {
      "name": "disabled",
      "type": "boolean",
      "default": false
    }
  ],
  "events": [
    {
      "name": "click",
      "description": "Fired when button is clicked",
      "bubbles": true,
      "composed": true
    }
  ],
  "llm": {
    "intent": "Trigger user actions",
    "allowedContexts": ["forms", "dialogs", "toolbars"],
    "antiPatterns": ["Multiple primary buttons per view"]
  }
}

    Prop Object¶

    Represents a configurable property of a component.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. Prop name as used in code.
    type string REQUIRED. Data type (string, number, boolean, enum, array, object).
    description string What the prop controls. CommonMark syntax MAY be used.
    required boolean Whether the prop must be provided. Default: false.
    default any Default value if not specified.
    enumValues [string] Allowed values for enum types.
    constraints Prop Constraints Object Validation rules for the prop value.

    Prop Constraints Object¶

    Defines validation rules for a property value.

    Fixed Fields¶

    Field Name Type Description
    min number Minimum value for number types.
    max number Maximum value for number types.
    minLength integer Minimum length for string types.
    maxLength integer Maximum length for string types.
    pattern string Regex pattern for string validation.
    step number Valid increments for number types.

    Component Event Object¶

    Represents a CustomEvent emitted by a component.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. Event name (e.g., "change", "submit").
    description string When this event is emitted. CommonMark syntax MAY be used.
    bubbles boolean Whether event bubbles through DOM. Default: false.
    composed boolean Whether event crosses shadow DOM boundary. Default: false.
    cancelable boolean Whether event can be canceled. Default: false.
    detail [Event Detail Field Object] Schema of the event.detail payload.

    Event Detail Field Object¶

    Describes a field in the event.detail payload.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. Field name in the detail object.
    type string REQUIRED. Data type of the field.
    description string What this field contains.

    Slot Object¶

    Represents a content insertion point for composition.

    Fixed Fields¶

    Field Name Type Description
    name string REQUIRED. Slot name.
    description string What content belongs in this slot. CommonMark syntax MAY be used.
    required boolean Whether content must be provided. Default: false.
    allowedComponents [string] Component IDs that can be inserted.

    Variant Object¶

    Represents a visual or behavioral variant of a component.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier for the variant.
    name string REQUIRED. Display name (e.g., "Primary", "Secondary").
    description string When to use this variant. CommonMark syntax MAY be used.
    isDefault boolean Whether this is the default variant. Default: false.
    tokenOverrides [Token Override Object] Tokens that differ from base component.

    State Object¶

    Represents an interactive state of a component.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier (hover, focus, disabled, etc.).
    name string Display name for the state.
    description string When this state applies. CommonMark syntax MAY be used.
    tokenOverrides [Token Override Object] Tokens that change in this state.

    Token Override Object¶

    Specifies a token value that differs for a variant or state.

    Fixed Fields¶

    Field Name Type Description
    tokenId string REQUIRED. Token being overridden.
    value string REQUIRED. Override value.

    Constraints Object¶

    Defines usage limitations for a component.

    Fixed Fields¶

    Field Name Type Description
    minWidth string Minimum recommended width.
    maxWidth string Maximum recommended width.
    maxChildren integer Maximum number of child elements.
    requiredParent string Required parent component ID.
    forbiddenChildren [string] Components that cannot be nested inside.
    responsiveBehavior string How the component adapts to viewport changes.

    LLM Context Object¶

    Provides optimization fields for AI code generation.

    Fixed Fields¶

    Field Name Type Description
    intent string Primary purpose of this element.
    allowedContexts [string] Situations where this element SHOULD be used.
    forbiddenContexts [string] Situations where this element SHOULD NOT be used.
    dependencies [string] Other elements this one requires.
    exampleUsage [string] Code snippets demonstrating correct usage.
    antiPatterns [string] Common mistakes to avoid.
    semanticMeaning string User-facing meaning of this element.
    relatedComponents [string] Commonly used together with.
    priorityScore integer Preference score (higher = prefer over alternatives).

    LLM Context Object Example¶

    {
  "intent": "Primary action button for form submissions",
  "allowedContexts": ["form-submit", "modal-confirm", "primary-cta"],
  "forbiddenContexts": ["destructive-action", "navigation"],
  "exampleUsage": [
    "<Button variant=\"primary\">Submit</Button>",
    "<Button variant=\"primary\" disabled={isLoading}>Save</Button>"
  ],
  "antiPatterns": [
    "Don't use for destructive actions like delete",
    "Avoid multiple primary buttons in the same view"
  ]
}

    Pattern Object¶

    Represents a multi-component UX solution.

    Fixed Fields¶

    Field Name Type Description
    id string REQUIRED. Unique identifier.
    name string REQUIRED. Display name.
    description string REQUIRED. Purpose and when to use it. CommonMark syntax MAY be used.
    category string Groups related patterns (e.g., "forms", "navigation").
    components [Pattern Component Object] REQUIRED. Components that make up this pattern.
    layout Pattern Layout Object How components are arranged.
    behavior string Description of the interaction flow.
    variations [Pattern Variation Object] Different configurations.
    accessibility Pattern A11y Object Accessibility requirements.
    llm LLM Context Object AI code generation fields.
    documentationUrl string URL to detailed documentation.

    Pattern Component Object¶

    References a component used in a pattern.

    Fixed Fields¶

    Field Name Type Description
    componentId string REQUIRED. Reference to a component from the components list.
    role string Component's role in this pattern.
    required boolean Whether this component is essential. Default: false.
    quantity string How many instances (e.g., "1", "1+", "0-1").
    configuration object Default props for this usage.

    Appendix C: File Extension¶

    DSS documents SHOULD use the following file extensions:

    • .dss.json for JSON format
    • .dss.yaml or .dss.yml for YAML format
    • design-system.json for single-file specifications
